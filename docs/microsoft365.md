# Microsoft 365 setup — UNCONFIGURED / UNVERIFIED

These are implementation notes, not a connected integration. Tenant permissions, licensing, connector support and destination IDs must be verified by the owner. Do not enable a sending flow until a sandbox test and approval.

1. Download the Power Automate table workbook from the app after approvals. Upload it to a dedicated SharePoint document library. Give the service connection least-privilege access. Create a SharePoint Receivables list: PostingKey (single text, enforce unique values), SourceHash, DocumentType, Supplier, Customer, DocumentNumber, InvoiceDate, DueDate, Currency, Net, VAT, Total, LinkedInvoice, SourceFile and imported timestamp. Store source PDFs in a restricted library and record links.
2. Create an import flow using Excel Online (Business) **List rows present in a table**, library/file and `PostedReceivables`. Enable pagination: the default listing can return only 256 rows. Read approved rows only. Map columns explicitly; test typed dates and GBP decimal values. Avoid simultaneous Excel writers and check connector locking/size limitations. See [official connector reference](https://learn.microsoft.com/en-us/connectors/excelonlinebusiness/).
3. For each row, use PostingKey as the idempotency identity. Check for an existing item, then create; the SharePoint unique constraint must still enforce uniqueness to close the race between lookup and create. Treat a confirmed duplicate as an already imported item, not a second posting. Keep trigger/loop concurrency at one initially. Record success/failure separately; retries must reuse the same key. A conflicting existing key with different values needs human review, not silent overwrite. Reimport the same workbook twice and confirm row count is unchanged.
4. Keep payments in a separate list keyed uniquely by PaymentId and credits keyed by PostingKey. Allocate credit only to an existing invoice for the same customer. The posted register includes invoice and credit documents; do not sum all document totals as aged debt. Initially upload the app's dated AgedDebt snapshot, including CustomerSummary, to a separate reporting location. A cloud scheduler cannot recalculate the local SQLite portfolio; a fresh dated snapshot must be supplied or the calculation must be reimplemented and verified in a service.
5. For a scheduled overdue summary, create a Scheduled cloud flow with Recurrence, for example weekdays at 09:00 in the London timezone (choose the tenant's supported timezone identifier and verify daylight-saving behavior). Read the latest aged snapshot, validate its reporting date equals today's London date, and stop/report a stale snapshot to the owner rather than send inaccurate debt. Select positive overdue balances, group by customer, and include bucket totals, reporting date, unresolved count and report link. The SharePoint imported register does not alone provide payment-adjusted aged balances.
6. Create a NotificationRuns list with a unique RunKey such as `overdue|2026-10-10|channel-id|v1`, state Pending/Sent/Unknown, timestamp and message ID. Acquire the unique key before sending and set concurrency to one. Existing Sent means skip. A timeout after sending creates an ambiguous state: mark Unknown and require manual reconciliation; do not blindly retry a message. Exactly-once delivery is not guaranteed by Teams. Persist the message ID on success. Use [Post a message in a chat or channel](https://learn.microsoft.com/en-us/power-automate/teams/send-a-message-in-teams) only after destinations and approval are verified.

Acceptance checks: sandbox import with two replays; conflicting duplicate; payment replay; partial payment; credit allocation; all aging boundaries; stale snapshot; concurrent trigger; connector throttling/retry; denied permissions; ambiguous message timeout; no actual production send. Record verified flow IDs, site/library/list IDs, channel ID, owner, test date and evidence before changing the status above. They are all currently unset.

Empty Excel tables include one blank template row so the named table exists before the first approval. Filter rows to `status = approved` and a nonempty `posting_key` before importing. Never create a SharePoint item from that blank template row.
